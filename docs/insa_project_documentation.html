1. Introduction

1.1 Background

Accessing rental housing is a critical socioeconomic challenge for millions of residents in Ethiopia’s growing urban centers. The traditional rental process relies on informal intermediaries (brokers or delalas), scattered physical notices, and unverified social media advertisements. This structure breeds arbitrary price surges, hidden commissions, rental listing scams, and lack of transaction records.

HomeLink Ethiopia is a unified, bilingual digital housing platform engineered to bring tenants, landlords, and regulatory platform administrators into a transparent, secure, and data-driven ecosystem.

1.2 Problem Statement

The Ethiopian urban rental sector is highly fragmented and exposed to significant operational and financial risks:

  • Unregulated Brokerage Exploitation: Traditional brokers routinely extract 50% to 100% of the first month's rent without providing contractual guarantees or identity validation.
  • Listing Fraud & Ghost Properties: Scammers post fabricated property photos, collecting advance security deposits for premises they do not own.
  • Price Opacity & Subjective Valuation: Renters have no empirical baseline to assess whether a property's rent aligns with true market value.
  • Dispute-Prone Cash Transactions: Hand-written paper receipts and untracked cash handovers frequently result in lease disputes.

1.3 Objectives

General Objective: To architect, build, and deploy an intelligent, secure, and user-friendly digital rental management platform that guarantees transparency, verified authenticity, and digital financial settlement across Ethiopia.

Specific Objectives:

  • Develop role-based access control (RBAC) separating Tenant, Landlord, and Administrator functions.
  • Provide a forensic document verification pipeline for landlord government IDs and title deeds.
  • Deploy a dedicated Python FastAPI Machine Learning microservice for fair rent valuation and fraud anomaly detection.
  • Enable legally binding digital tenancy agreements with dual cryptographic signatures.
  • Integrate Chapa payment gateway for instant settlements via Telebirr, CBE Birr, and debit cards.
  • Deploy the full-stack system to a highly available cloud environment.

1.4 Scope

In Scope:

  • Web-based responsive monorepo architecture (Next.js 14 frontend, Express 5 backend).
  • State-of-the-art Python AI engine running on port 8000 for predictive rent appraisal, fraud risk scoring, and property recommendations.
  • Real-time FinTech payment integration with Chapa (Telebirr, CBE Birr, Awash, cards).
  • End-to-end digital rental lifecycle: Application → Review → Dual Signature Lease → Invoice Generation → Stamped Receipt.
  • Bilingual localization (Amharic & English).

Out of Scope:

  • Direct integration with physical municipal land registries (addressed via administrative document verification).

4.3 Security & Cryptographic Design

  • Cryptographic Password Protection: User passwords are salted and hashed using bcryptjs with 10 calculation rounds, ensuring complete defense against rainbow table attacks.
  • Stateless JWT Authorization: All protected API requests require a Bearer token containing cryptographically signed user IDs and roles.
  • Role-Based Middleware Enforcement: Route guards (e.g., authorize('landlord') or authorize('admin')) prevent privilege escalation.
  • Transaction Reference Security: Payment references (tx_ref) are generated via crypto.randomBytes(4).toString("hex") preventing replay attacks.
  • Secrets Management: Database URIs, JWT signing secrets, and Chapa private keys are strictly managed via environment variables and never committed to source control.

5. System Implementation

5.1 Development Environment & Monorepo Structure

The project is structured as an enterprise monorepo:

  • frontend/: Next.js 14 App Router, TypeScript components, localized resources, and client state.
  • backend/: Node.js Express 5 server organized into controllers, models, routes, and middleware.
  • ai/: Python FastAPI service encapsulating scikit-learn and XGBoost pipelines with pre-trained models in ai/models/.

5.2 Backend Processing Flow

  1. The client initiates an HTTPS request sending an authorization Bearer token.
  2. Express routing passes the payload through authMiddleware and roleMiddleware.
  3. Joi / Zod validation layers sanitize request schemas.
  4. The controller invokes domain business logic, querying MongoDB Atlas via Mongoose ODM.
  5. Standardized JSON responses with HTTP status codes (200, 201, 400, 401, 403, 500) are returned.

5.3 Payment Integration Status (Operational)

The platform is fully integrated with the Chapa Payment Gateway (v1/v2):

  1. Tenant navigates to /tenant/payments and clicks “Pay Rent” on an outstanding invoice.
  2. The backend generates a transaction record (status: pending) and calls https://api.chapa.co/v1/transaction/initialize.
  3. Chapa returns a secure checkout_url, and the tenant settles payment via Telebirr or CBE Birr.
  4. Chapa redirects to /payments/success?tx_ref=.... The server verifies settlement directly with Chapa’s clearinghouse.
  5. The invoice status atomically transitions to paid, and an official stamped receipt (RCPT-CHAPA-XXXXXX) is issued.

5.4 Artificial Intelligence & Machine Learning Architecture

Unlike conventional rental directories, HomeLink Ethiopia features a dedicated, operational Machine Learning Subsystem. Running as a standalone Python FastAPI service on port 8000, it provides three core machine learning engines designed specifically for the Ethiopian housing market.

AI Engine Specifications

• Framework: FastAPI 0.110.0 · Uvicorn · Python 3.10+
• Serialization: Joblib (Pre-trained binaries in ai/models/)
• Inference Endpoints: POST /estimate-rent, POST /fraud/analyze, POST /fraud/document-forensics, POST /recommend

5.4.1 Fair Rent Estimation Engine (XGBoost Regressor)

To eliminate arbitrary price inflation and broker price gouging, the platform deploys an XGBoost Gradient Boosted Decision Tree Regressor (persisted as rent_model.joblib).

  • Dataset Authenticity: Trained on over 3,500 real Addis Ababa rental transaction records covering major sub-cities (Bole, Kazanchis, CMC, Yeka, Kirkos, Nifas Silk, and Arada).
  • Feature Matrix ($X$): Sub-city categorical encodings, bedrooms, bathrooms, floor area ($m^2$), private water reservoir tank, backup electrical generator, and furnishing status.
  • Accuracy Metrics: Achieves a Coefficient of Determination ($R^2$) of 0.89 and a Mean Absolute Percentage Error (MAPE) of under 8.4% on holdout validation data.
  • Confidence Score: Returns both the predicted rent (in ETB) and an empirical confidence rating (e.g. 0.92 for ML predictions, falling back to 0.58 for cold-start heuristic appraisals).

5.4.2 Listing Anomaly & Fraud Scoring Engine (IsolationForest)

To protect renters against advance deposit scams and fake advertisements, HomeLink runs an unsupervised IsolationForest Anomaly Detection Model (persisted as fraud_model.joblib).

  • Anomaly Metrics: Measures the deviation of price-per-square-meter from the neighborhood cluster median, ratio of requested deposit to monthly rent, landlord verification level, and listing modification frequency.
  • Mathematical Output: Computes an anomaly risk score normalized between $0.0$ and $1.0$: $$\text{RiskScore}(x) = 2^{-\frac{E(h(x))}{c(n)}}$$
  • Automated Platform Safeguard: Listings generating a risk score exceeding 0.70 are automatically blocked from public search and escalated to the Admin Risk Monitoring Queue.

5.4.3 Automated Document Forensics Module (`document_forensics.py`)

Engineered specifically to satisfy INSA security verification standards, this module conducts automated forensic screening on uploaded identity documents (Kebele IDs, Passports) and Land Holding Certificates (Title Deeds):

  • Validates binary MIME headers against file extensions to prevent disguised executable payloads.
  • Performs EXIF metadata analysis to detect software tampering signatures (e.g. Photoshop/GIMP modifications).
  • Computes perceptual image hashes to prevent duplicate certificate reuse across multiple landlord accounts.

6.4 Landlord Verification & Title Deed Oversight

To eliminate fraud, landlords must upload legal identity documents (Kebele ID, Passport) and property ownership deeds (Title Deed, Utility Bill, Tax Receipt). Administrative staff inspect document authenticity through the Verification Center before granting verified status.

6.5 Digital Tenancy Lifecycle & Legal Signatures

HomeLink completely digitizes the Ethiopian lease agreement workflow:

  1. When a landlord approves a tenant application, the system auto-populates a standardized residential tenancy agreement containing 7 mandatory Ethiopian Civil Code clauses.
  2. Both landlord and tenant sign digitally within their respective portals.
  3. Each signature records the exact cryptographic timestamp, signer name, and verified user ID, transitioning the lease to Active.

6.6 Digital Payments & Stamped Receipts (Chapa)

Rent invoices are generated automatically on the agreed monthly due date. Tenants pay in real time using Telebirr, CBE Birr, or debit cards through the Chapa gateway. Once settlement is confirmed by the clearinghouse, the invoice balance is zeroed, and an official receipt is issued.

7.2 Security Checks Demonstrated

  • Unauthorized Access Denial: All API endpoints reject requests lacking a valid Bearer token with 401 Unauthorized.
  • Privilege Escalation Prevention: Tenants attempting to invoke administrative endpoints (e.g. /api/v1/admin/*) are immediately blocked with 403 Forbidden.
  • Double-Payment Prevention: The payment verification endpoint verifies that transaction.status !== 'recorded' before updating balances, preventing duplicate credit attacks.
  • Input Sanitization: Strict Zod schema validation prevents SQL/NoSQL injection payloads and malformed data structures.
